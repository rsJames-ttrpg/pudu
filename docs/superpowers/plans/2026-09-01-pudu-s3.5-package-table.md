# pudu S3.5 — Package Table Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retire the `pudu.lock` "sidecar" in favour of `<third_party_dir>/packages.toml`, "the package table", with no behavioural change.

**Architecture:** A rename in five independently reviewable slices. Types and module first (invisible to users, so the tree stays green with no test-string churn), then the user-visible strings and the file path together with the tests that assert on them, then the one new test that earns the version reset, then an adjacent type rename, then documentation. No task leaves the tree red.

**Tech Stack:** Rust 2024, MSRV 1.88, `toml`, `serde`, `thiserror` + `miette`, `insta` snapshots, `assert_cmd` + `httpmock` integration tests.

**Spec:** `docs/superpowers/specs/2026-09-01-pudu-s3.5-package-table-design.md`

## Global Constraints

- MSRV floor is **1.88**. `cargo +1.88 check --all-targets` must pass.
- `cargo fmt --all -- --check` and `cargo clippy --all-targets -- -D warnings` must pass at every commit.
- **Zero behavioural change.** No exit code, no field, no ordering, no rendering rule, and no control flow may differ. Only names, strings, the file path, and the version integer change.
- `ExitCode::Stale = 5` is unchanged. Every other exit code is unchanged.
- The file is `<third_party_dir>/packages.toml`. Prose calls it **the package table**. The word "sidecar" is retired everywhere outside `docs/superpowers/plans/` and the S3.5 spec.
- `docs/superpowers/plans/2026-08-31-pudu-s3-vendor.md` is a historical record of shipped work and **must not be edited**.
- Determinism is an exit criterion: rendering stays hand-written, `BTreeMap` ordering is preserved, two runs must be byte-identical.

### Task 3: Pin the premise of the version reset

The version reset to `1` is only safe if a stray `pudu.lock` is genuinely never read. That is an assumption, so it gets a test.

**Files:**
- Test: `tests/vendor.rs`

**Interfaces:**

- [ ] **Step 1: Write the failing test**

Add to `tests/vendor.rs`:

```rust
#[test]
fn an_old_pudu_lock_is_not_read_as_a_package_table() {
    // S3.5 reset the format version to 1 on the grounds that the rename makes
    // a collision impossible: no file an earlier pudu wrote can be opened as
    // `packages.toml`. That argument is only sound if a stray `pudu.lock` is
    // genuinely never read — so this test builds the exact tree that would
    // expose the mistake, one holding complete and valid vendor data under
    // the old name and nothing under the new one.
    let f = Fixture::new();
    f.cmd().arg("vendor").assert().success();
    let contents = f.table();

    let old = f.table_path().parent().unwrap().join("pudu.lock");
    std::fs::rename(f.table_path(), &old).unwrap();

    let out = f.cmd().args(["vendor", "--check"]).output().unwrap();
    assert_eq!(
        out.status.code(),
        Some(5),
        "a tree holding only a pudu.lock must read as having no table at all"
    );
    let stderr = String::from_utf8(out.stderr).unwrap();
    assert!(
        stderr.contains("packages.toml has no entry for `left-pad@1.3.0`"),
        "every package must be reported missing rather than carried over from pudu.lock:\n{stderr}"
    );

    assert_eq!(
        std::fs::read_to_string(&old).unwrap(),
        contents,
        "pudu must not delete or rewrite a file it no longer writes"
    );
}
```
